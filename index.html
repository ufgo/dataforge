Введение в DataForge Introduction to DataForge

DataForge — это кроссплатформенное приложение с графическим интерфейсом, предназначенное для организации баз данных игровых проектов. Оно решает проблему хаоса в статических ресурсах игры (таких как характеристики оружия, параметры монстров, балансировочные коэффициенты квестов и сценарии диалогов).

DataForge is a cross-platform desktop application with a graphic user interface designed to organize game project databases. It resolves content chaos in static game resources (such as weapon attributes, monster stats, quest balance variables, and dialogue scripts).

В отличие от тяжелых СУБД (SQL) или обычных текстовых редакторов, DataForge предлагает интуитивный интерфейс, где структура данных (схема) и сам контент разделены, но редактируются в одном месте.

Unlike heavy databases (SQL) or basic text editors, DataForge offers an intuitive interface where the data structure (schema) and the content itself are separated but edited together in one workspace.

💡 Универсальность для любых движков: 💡 Universal for All Engines: DataForge спроектирован так, чтобы не зависеть от конкретной платформы. Независимо от того, используете ли вы Unity, Unreal Engine, Godot, Defold или LÖVE2D, вы можете экспортировать свои структуры данных в форматы, поддерживаемые любым современным движком. DataForge is designed to be completely engine-agnostic. Whether you use Unity, Unreal Engine, Godot, Defold, or LÖVE2D, you can export your data structures into formats supported by any modern game engine.

Ключевые Концепции Key Concepts

  • Категории (Categories)Categories — это описание структуры таблицы. Например, категория "Оружие". — descriptions of table structures. For example, the "Weapons" category.
  • Поля (Fields)Fields — столбцы с определенным типом данных в категории. Например, `damage` (число) или `icon` (путь к картинке). — columns with a specific data type in a category. For example, `damage` (number) or `icon` (image path).
  • Макет (Layout)Layout — схема того, как поля будут скомпонованы на экране при редактировании. Позволяет структурировать форму ввода и визуально группировать поля по смыслу. — layouts of how fields are arranged visually on screen. Allows structuring input forms and grouping properties by meaning.
  • Элементы (Items)Items — конкретные строки данных. Например, `Sword of Souls` со всеми его характеристиками. — concrete rows of data. For example, `Sword of Souls` with all its values.

Установка и Требования Installation & Requirements

Приложение DataForge поставляется в виде готовых бинарных файлов для операционных систем macOS и Windows. Вам не требуется скачивать исходный код или настраивать среду разработки для запуска.

DataForge is distributed as prebuilt binaries for macOS and Windows operating systems. You do not need to download the source code or set up a developer compilation workspace to run it.

Категории и Наследование Categories & Inheritance

Создание любой базы данных в DataForge начинается с Категорий (Categories). Каждая категория представляет собой описание структуры таблицы однородных объектов (например, «Оружие», «Квесты» или «Характеристики персонажей»).

Building any database in DataForge starts with **Categories**. Each category describes the data structure schema of similar entities (e.g., "Weapons", "Quests", or "Character Stats").

Создание Категории Creating a Category

В левой панели приложения найдите кнопку + рядом с заголовком категорий. В модальном окне укажите следующие параметры:

In the left sidebar of the application, click the + button next to the categories header. In the modal dialog, configure the following properties:

  • ID:ID: Уникальный системный идентификатор (например, weapons). Используется в качестве ключа при экспорте. Допускаются только латинские буквы, цифры и знаки подчеркивания. Unique system identifier (e.g., weapons). Used as the main key during export. Only alphanumeric characters and underscores are allowed.
  • Name:Name: Отображаемое имя категории в интерфейсе редактора (например, "Холодное оружие"). Human-readable category title displayed in the editor UI (e.g., "Melee Weapons").
  • Родительская категория (Parent Category):Parent Category: Позволяет указать существующую категорию в качестве родителя, выстраивая иерархическое дерево данных. Allows selecting an existing category as a parent, building a hierarchical structure tree.

Наследование Полей и Макетов Fields & Layout Inheritance

В DataForge реализована мощная система наследования структуры данных, избавляющая от повторного ручного описания схем:

DataForge features a robust schema inheritance system, saving developers from manually recreating schemas for similar entities:

  • Наследование структуры (Fields Inheritance): Fields Inheritance: При включенном переключателе inheritFields в настройках категории, дочерняя таблица автоматически получает все поля своей родительской категории (и её предков выше по иерархии). When the inheritFields toggle is enabled in category settings, the child table automatically inherits all fields from its parent category (and its ancestors up the hierarchy tree).
  • Переопределение свойств полей (Overrides): Property Overrides: Дочерняя категория может переопределить настройки унаследованного поля (например, изменить тип, регулярное выражение или границы чисел), просто создав поле с тем же ID. A child category can override properties of any inherited field (e.g., changing the type, regex constraints, or number bounds) simply by creating a field with the exact same ID.
  • Наследование макетов (Layout Fallback): Layout Fallback: Если в дочерней категории не настроена вкладка визуального макета Layout, редактор автоматически использует макет родительской категории для отрисовки карточек элементов. If a child category does not define its own visual form layout on the **Layout** tab, the editor automatically inherits the layout template of its parent category.

Fields define the data schema of items inside the selected category. Each field has a unique ID, label name, and data type.

Настройки валидации и ограничений (Field Config) Validation Constraints (Field Config)

При добавлении или редактировании поля в схеме категории вы можете настроить параметры его валидации:

When creating or editing a field, you can configure several validation constraints and presentation options:

  • Обязательное (Required):Required: Поле не может оставаться пустым при сохранении элемента. The field must be filled out before saving the item.
  • Уникальное (Unique):Unique: Редактор проверяет уникальность значения этого поля во всех элементах категории, предотвращая дубликаты. The editor enforces value uniqueness across all items in this category to prevent duplicate values.
  • Регулярное выражение (Regex):Regex: Проверка текстовых строк на соответствие паттерну (например, маска артикула ^[A-Z]{3}-\d{4}$). Evaluates text strings against a regular expression pattern (e.g. matching an item code like ^[A-Z]{3}-\d{4}$).
  • Локализация (Localized):Localized: Указывает, что поле предназначено для хранения языковых ключей (поддерживающих переводы). Indicates that the field values store translation keys supporting localizations.
  • Многострочность (Multiline):Multiline: Отображает многострочное поле ввода (textarea) вместо одной текстовой строки. Renders a multiline textarea input box instead of a single-line input.
  • Отражать имя (Reflects Name):Reflects Name: Значение этого строкового поля будет автоматически подставляться в качестве заголовка элемента в дереве сущностей (вместо технического ID элемента). Automatically sets the value of this string field as the display label of the item in the sidebar explorer tree (instead of displaying its raw technical ID).
  • Границы диапазона (Min, Max, Step):Number Bounds (Min, Max, Step): Для числового типа Number — задаёт границы ввода и шаг (например, шаг 0.1 для плавных значений или 1 для целых чисел). For the Number type, sets the input constraints and stepping value (e.g., step 0.1 for decimal fractions or 1 for integers).

Наследование значений и переопределение (Система Замков) Value Inheritance & Overrides (The Lock System)

DataForge реализует гибкую систему наследования значений с помощью замков (Locks):

DataForge features a default value inheritance scheme driven by interactive padlock status icons:

  • Default Values:Default Values: На уровне категории (вкладка Default Values) вы можете определить значения по умолчанию для всех полей. In category settings (Default Values tab), you can define default values for all category fields.
  • Открытый замок (Unlocked):Unlocked (Default): По умолчанию все поля нового элемента наследуют дефолтные значения из категории. Если изменить значение по умолчанию в настройках категории, оно мгновенно обновится во всех элементах с открытым замком. All newly created items inherit the defaults defined in the category. If you change a category default, it instantly updates in all items with an Unlocked padlock.
  • Закрытый замок (Locked / Override):Locked (Override): Если изменить поле в конкретном элементе вручную, замок автоматически закрывается. Это означает, что локальное значение переопределено и изолировано от изменений дефолтных значений на уровне категории. Вы можете сбросить переопределение в любой момент, нажав на замок. Manually editing a field value in a specific item automatically clicks shut the padlock icon. This isolates the field value, preserving your custom edit from any future category-level default value updates. You can reset a value back to defaults at any time by clicking the padlock icon.

Связи между Категориями (Relations / References) Category Relationships (Relations & References)

Связи (отношения) позволяют объединять разрозненные категории в единую структурированную базу данных. Они реализуются через специальный тип поля Reference.

Relations connect independent categories into a structured, unified database. They are established via the Reference field type.

  • Настройка связи:Relation Settings: При создании поля типа Reference в настройках схемы категории вы указываете целевую категорию (например, в свойствах персонажа поле weapon_id будет ссылаться на категорию weapons). When creating a Reference field, select the target category (e.g., in a character profile, a weapon_id field points to the weapons category).
  • Интерфейс заполнения:Data Input UI: При редактировании элемента DataForge автоматически подгружает все элементы из целевой категории и отображает удобный выпадающий список. Вместо ручного ввода ID разработчик выбирает нужный элемент по его имени. While editing an item, DataForge automatically loads all items from the target category into a user-friendly dropdown. Game designers select items by their display name instead of typing technical IDs.
  • Типы связей:Relation Types:
    • Одиночная связь (One-to-One / One-to-Many):Single Reference (One-to-One / One-to-Many): Обычное поле Reference, содержащее ссылку на один элемент. Например, класс персонажа указывает на свое стартовое снаряжение. A regular reference field holding a single link, like a character pointing to their starting weapon.
    • Множественная связь (Many-to-Many):Collection of References (Many-to-Many): Комбинация типов Collection и Reference. Позволяет хранить массив ссылок. Например, торговец ссылается на список товаров, которые он продает, или монстр содержит список активных умений (references на категорию умений). A combination of Collection and Reference types. Allows storing an array of links (e.g., a shop merchant holding a list of references to sellable items, or a monster pointing to an array of active spells).
  • Целостность данных:Data Integrity: При экспорте сохраняются только строковые идентификаторы (ID) связанных элементов, что делает итоговый JSON/CSV чистым, легким и готовым для ручной или автоматической сборки связей на стороне игрового движка. Only the string identifier (ID) of the linked entity is exported in the final JSON/CSV payload. This keeps the data payload lightweight and leaves connection resolving to the runtime game engine loader.

Настройка Внешнего Вида (Layouts) Visual Forms & Layouts

Когда у категории много полей (например, 20-30 характеристик для сложного монстра), редактировать их обычным списком становится неудобно. DataForge предоставляет визуальный инструмент настройки формы — Layout Tree Editor.

When a category has many fields (e.g., 20-30 attributes for a complex boss monster), editing them in a simple flat list becomes cumbersome. DataForge provides an interactive tool to design custom editing forms — the Layout Tree Editor.

Вкладка Layout позволяет визуально сконструировать форму заполнения данных с помощью древовидной структуры узлов:

The Layout tab allows visually building a data input form template using a hierarchical tree structure of layout nodes:

Доступные элементы разметки: Available Layout Elements:

  • Контейнеры (Containers):Containers: Группируют несколько полей. Вы можете выбрать направление группировки: Horizontal (поля выстроятся в ряд) или Vertical (друг под другом). Group multiple fields. You can select the flow direction: Horizontal (fields are placed side-by-side) or Vertical (fields stack on top of each other).
  • Заголовки (Headers):Headers: Добавляют текстовые разделители для визуального разделения блоков формы (например: "Базовые параметры", "Боевые характеристики"). Add text labels to visually group form sections (e.g., "Core Settings", "Combat Attributes").
  • Разделители (Separators):Separators: Простые линии-разделители для отделения одной группы параметров от другой. Simple horizontal rule dividers to separate one parameter group from another.

Управление и опции отображения полей: Field Presentation Properties:

Вы можете перетаскивать созданные поля в контейнеры, настраивать их последовательность, а также задавать уникальные свойства для отображения полей в макете:

You can drag-and-drop fields into containers, organize their tab order, and configure custom layout properties for specific fields:

  • Растянуть (Expand):Expand: Флаг заставляет поле занимать всё доступное горизонтальное пространство в ряду (полезно для адаптивного распределения ширины полей в горизонтальных контейнерах). Forces the field to stretch and fill all available horizontal space in a row (useful for auto-scaling column widths inside horizontal containers).
  • Встроить связь (Embed Reference):Embed Reference: Доступно только для полей типа Reference. При активации этого флага вместо выпадающего списка выбора ID, прямо внутрь карточки текущего элемента будут **встроены поля редактирования связанного объекта**. Это позволяет редактировать связанные сущности «in-place» без перехода в другие категории. Only available for Reference type fields. Activating this option hides the standard dropdown ID selector and instead **embeds the edit form fields of the linked entity** directly into the parent card. This allows game designers to edit nested objects inline without context-switching.

Импорт и Экспорт Данных Import & Export

DataForge поддерживает двусторонний обмен данными, позволяя легко переносить информацию между редактором, внешними таблицами и файлами конфигурации вашей игры.

DataForge supports two-way data exchange, making it easy to transfer information between the editor, external spreadsheets, and your game configuration files.

Экспорт Данных Exporting Data

Экспорт вызывается через кнопку Export в верхнем меню приложения. Доступны следующие форматы:

Exporting is initiated by clicking the Export button in the top menu of the app. The following formats are supported:

  1. Lua Tables (.lua):Lua Tables (.lua):

    При использовании плагина автоэкспорта Lua приложение генерирует готовые файлы .lua в виде стандартных ассоциативных массивов (таблиц), возвращаемых через return. Это наиболее производительный способ загрузки данных в Lua-совместимых движках, поскольку файлы компилируются и загружаются нативно, полностью исключая стадию ручного парсинга строк JSON во время выполнения игры.

    When using the Lua Auto-Export plugin, the app generates ready-to-use .lua files returning standard associative tables. This is the most performant way to load data into Lua-compatible engines, as files are compiled and loaded natively, bypassing raw JSON parsing at runtime.

  2. JSON (.json):JSON (.json):

    Экспортирует всю базу данных в один компактный JSON-объект, либо генерирует отдельные JSON-файлы для каждой категории. Идея подходит для универсального импорта в Unity, Unreal Engine или Godot.

    Exports the entire database into a single compact JSON object, or generates separate JSON files for each category. Perfect for importing into Unity, Unreal Engine, or Godot.

  3. CSV (.csv):CSV (.csv):

    Экспортирует выбранную категорию в формате плоской таблицы. Удобно для импорта в Google Sheets, Excel или для движков, оптимизированных под табличные структуры.

    Exports the selected category as a flat table sheet. Useful for Google Sheets, Microsoft Excel, or engines optimized for table parsing.

Импорт Данных Importing Data

Импорт в DataForge позволяет быстро загружать существующие таблицы баланса или структурированные списки. Процесс импорта полностью автоматизирован: вместо загрузки данных в пустую категорию, редактор **автоматически создает новую категорию** на основе структуры импортируемого файла.

DataForge's import utility allows for rapid uploading of balance sheets and item lists. The process is fully automated: rather than loading files into pre-existing empty schemas, the editor **automatically creates a new category** based on the structure of the imported file.

Как устроен процесс импорта: How the import workflow behaves:

  • Поддерживаемые форматы:Supported Formats: Вы можете импортировать файлы трех типов: You can import three file types:

    • Lua (.lua)Lua (.lua) — файлы, возвращающие Lua-таблицы (возвращаемое значение парсится через AST-анализатор).files returning a Lua table (parsed using AST syntax parser).
  • Автоматическое создание категории:Automatic Category Creation: Имя новой категории и её уникальный ID формируются на основе имени импортируемого файла (например, файл items_db.csv создаст категорию items_db). Если категория с таким именем уже существует в проекте, редактор автоматически добавит числовой суффикс (например, items_db_1). The new category name and its unique ID are derived from the imported filename (e.g., items_db.csv creates the category items_db). If a category with the same ID already exists, a number suffix is appended (e.g., items_db_1).

DataForge сканирует свойства импортируемых элементов и автоматически создает подходящие поля, определяя типы данных на лету: You don't need to configure category fields beforehand.     • Числа распознаются как тип Number.Numbers are resolved as type Number.

  • Окно настроек импорта (Import Settings):Import Settings Modal Window: Перед финальной загрузкой открывается модальное окно настроек: Before finalizing the import, a configuration window opens:

Разработка Плагинов (API) Plugin Development (API)

DataForge поддерживает динамическую загрузку плагинов, написанных на JavaScript. Вы можете расширять функционал редактора, регистрируя новые типы полей, добавляя собственные настройки и взаимодействуя со встроенным Tauri API.

DataForge supports dynamic loading of custom JavaScript plugins. You can extend the editor by registering custom field types, defining plugin settings, and interacting with the native Tauri bridge.

Каждый плагин представляет собой один .js файл, который помещается в локальную папку плагинов приложения. Настройки и метаданные плагина парсятся из JSDoc-комментария в начале файла.

Each plugin is a single .js file placed inside the local plugins folder of the application. The plugin configuration and meta definitions are parsed dynamically from a JSDoc block at the beginning of the file.

Метаданные плагина Plugin Meta Properties

Каждый плагин представляет собой один .js файл. В начале файла должен присутствовать JSDoc-комментарий, содержащий следующие параметры: имя плагина (@name), краткое описание (@description), версию (@version), автора (@author) и перечень регистрируемых типов полей (@fields).

The JSDoc comment at the top of the plugin file must declare: the plugin name (@name), description (@description), version (@version), author (@author), and registered field type tags (@fields).
