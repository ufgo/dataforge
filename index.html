Введение в DataForge

DataForge — это кроссплатформенное приложение с графическим интерфейсом, предназначенное для организации баз данных игровых проектов. Оно решает проблему хаоса в статических ресурсах игры (таких как характеристики оружия, параметры монстров, балансировочные коэффициенты квестов и сценарии диалогов).

В отличие от тяжелых СУБД (SQL) или обычных текстовых редакторов, DataForge предлагает интуитивный интерфейс, где структура данных (схема) и сам контент разделены, но редактируются в одном месте.

💡 Универсальность для любых движков: DataForge спроектирован так, чтобы не зависеть от конкретной платформы. Независимо от того, используете ли вы Unity, Unreal Engine, Godot, Defold или LÖVE2D, вы можете экспортировать свои структуры данных в форматы, поддерживаемые любым современным движком.

Ключевые Концепции

  • Категории (Categories) — это описание структуры таблицы. Например, категория "Оружие".
  • Поля (Fields) — столбцы с определенным типом данных в категории. Например, `damage` (число) или `icon` (путь к картинке).
  • Макет (Layout) — схема того, как поля будут скомпонованы на экране при редактировании. Позволяет структурировать форму ввода и визуально группировать поля по смыслу.
  • Элементы (Items) — конкретные строки данных. Например, `Sword of Souls` со всеми его характеристиками.

Установка и Требования

Приложение DataForge поставляется в виде готовых бинарных файлов для операционных систем macOS и Windows. Вам не требуется скачивать исходный код или настраивать среду разработки для запуска.

Установка на macOS

  1. Перейдите во вкладку Релизы и скачайте сборку для macOS (файл .dmg).
  2. Откройте скачанный DMG-образ и перетащите иконку DataForge в папку Applications (Программы).
  3. ⚠️ Примечание безопасности: Так как приложение распространяется напрямую без публикации в Mac App Store, при первом запуске macOS может заблокировать его. Чтобы обойти это, кликните по иконке приложения правой кнопкой мыши (или зажав Control), выберите Открыть, а затем подтвердите запуск в появившемся окне.

Установка на Windows

  1. Перейдите во вкладку Релизы и скачайте исполняемый файл для Windows (портативная версия .exe).
  2. Перенесите файл в любую удобную для вас папку. Никакой дополнительной установки не требуется — приложение готово к работе.
  3. ⚠️ Примечание безопасности: Поскольку приложение распространяется напрямую, фильтр Windows SmartScreen может выдать предупреждение об "Неизвестном издателе". В этом случае нажмите ссылку Подробнее (More info), а затем кнопку Выполнить в любом случае (Run anyway).

Категории и Наследование

Создание любой базы данных в DataForge начинается с Категорий (Categories). Каждая категория представляет собой описание структуры таблицы однородных объектов (например, «Оружие», «Квесты» или «Характеристики персонажей»).

Создание Категории

В левой панели приложения найдите кнопку + рядом с заголовком категорий. В модальном окне укажите следующие параметры:

  • ID: Уникальный системный идентификатор (например, weapons). Используется в качестве ключа при экспорте. Допускаются только латинские буквы, цифры и знаки подчеркивания.
  • Name: Отображаемое имя категории в интерфейсе редактора (например, "Холодное оружие").
  • Родительская категория (Parent Category): Позволяет указать существующую категорию в качестве родителя, выстраивая иерархическое дерево данных.

Наследование Полей и Макетов

В DataForge реализована мощная система наследования структуры данных, избавляющая от повторного ручного описания схем:

  • Наследование структуры (Fields Inheritance): При включенном переключателе inheritFields в настройках категории, дочерняя таблица автоматически получает все поля своей родительской категории (и её предков выше по иерархии).
  • Переопределение свойств полей (Overrides): Дочерняя категория может переопределить настройки унаследованного поля (например, изменить тип, регулярное выражение или границы чисел), просто создав поле с тем же ID.
  • Наследование макетов (Layout Fallback): Если в дочерней категории не настроена вкладка визуального макета Layout, редактор автоматически использует макет родительской категории для отрисовки карточек элементов.

Поля, Валидация и Наследование Значений

Поля (Fields) определяют схему данных объектов внутри выбранной категории. Каждое поле имеет уникальный ID, отображаемое имя и тип данных.

Доступные типы данных (10 типов полей):

Boolean Логический переключатель (Да/Нет) Является ли предмет квестовым

Image Путь к изображению с предпросмотром в UI Иконка предмета, портрет персонажа

Настройки валидации и ограничений (Field Config)

При добавлении или редактировании поля в схеме категории вы можете настроить параметры его валидации:

  • Обязательное (Required): Поле не может оставаться пустым при сохранении элемента.
  • Уникальное (Unique): Редактор проверяет уникальность значения этого поля во всех элементах категории, предотвращая дубликаты.
  • Регулярное выражение (Regex): Проверка текстовых строк на соответствие паттерну (например, маска артикула ^[A-Z]{3}-\d{4}$).
  • Локализация (Localized): Указывает, что поле предназначено для хранения языковых ключей (поддерживающих переводы).
  • Многострочность (Multiline): Отображает многострочное поле ввода (textarea) вместо одной текстовой строки.
  • Отражать имя (Reflects Name): Значение этого строкового поля будет автоматически подставляться в качестве заголовка элемента в дереве сущностей (вместо технического ID элемента).
  • Границы диапазона (Min, Max, Step): Для числового типа Number — задаёт границы ввода и шаг (например, шаг 0.1 для плавных значений или 1 для целых чисел).

Наследование значений и переопределение (Система Замков)

DataForge реализует гибкую систему наследования значений с помощью замков (Locks):

  • Default Values: На уровне категории (вкладка Default Values) вы можете определить значения по умолчанию для всех полей.
  • Открытый замок (Unlocked): По умолчанию все поля нового элемента наследуют дефолтные значения из категории. Если изменить значение по умолчанию в настройках категории, оно мгновенно обновится во всех элементах с открытым замком.
  • Закрытый замок (Locked / Override): Если изменить поле в конкретном элементе вручную, замок автоматически закрывается. Это означает, что локальное значение переопределено и изолировано от изменений дефолтных значений на уровне категории. Вы можете сбросить переопределение в любой момент, нажав на замок.

Связи между Категориями (Relations / References)

Связи (отношения) позволяют объединять разрозненные категории в единую структурированную базу данных. Они реализуются через специальный тип поля Reference.

  • Настройка связи: При создании поля типа Reference в настройках схемы категории вы указываете целевую категорию (например, в свойствах персонажа поле weapon_id будет ссылаться на категорию weapons).
  • Интерфейс заполнения: При редактировании элемента DataForge автоматически подгружает все элементы из целевой категории и отображает удобный выпадающий список. Вместо ручного ввода ID разработчик выбирает нужный элемент по его имени.
  • Типы связей:
    • Одиночная связь (One-to-One / One-to-Many): Обычное поле Reference, содержащее ссылку на один элемент. Например, класс персонажа указывает на свое стартовое снаряжение.
    • Множественная связь (Many-to-Many): Комбинация типов Collection и Reference. Позволяет хранить массив ссылок. Например, торговец ссылается на список товаров, которые он продает, или монстр содержит список активных умений (references на категорию умений).
  • Целостность данных: При экспорте сохраняются только строковые идентификаторы (ID) связанных элементов, что делает итоговый JSON/CSV чистым, легким и готовым для ручной или автоматической сборки связей на стороне игрового движка.

Настройка Внешнего Вида (Layouts)

Когда у категории много полей (например, 20-30 характеристик для сложного монстра), редактировать их обычным списком становится неудобно. DataForge предоставляет визуальный инструмент настройки формы — Layout Tree Editor.

Вкладка Layout позволяет визуально сконструировать форму заполнения данных с помощью древовидной структуры узлов:

Доступные элементы разметки:

  • Контейнеры (Containers): Группируют несколько полей. Вы можете выбрать направление группировки: Horizontal (поля выстроятся в ряд) или Vertical (друг под другом).
  • Заголовки (Headers): Добавляют текстовые разделители для визуального разделения блоков формы (например: "Базовые параметры", "Боевые характеристики").
  • Разделители (Separators): Простые линии-разделители для отделения одной группы параметров от другой.

Управление и опции отображения полей:

Вы можете перетаскивать созданные поля в контейнеры, настраивать их последовательность, а также задавать уникальные свойства для отображения полей в макете:

  • Растянуть (Expand): Флаг заставляет поле занимать всё доступное горизонтальное пространство в ряду (полезно для адаптивного распределения ширины полей в горизонтальных контейнерах).
  • Встроить связь (Embed Reference): Доступно только для полей типа Reference. При активации этого флага вместо выпадающего списка выбора ID, прямо внутрь карточки текущего элемента будут **встроены поля редактирования связанного объекта**. Это позволяет редактировать связанные сущности «in-place» без перехода в другие категории.

Импорт и Экспорт Данных

DataForge поддерживает двусторонний обмен данными, позволяя легко переносить информацию между редактором, внешними таблицами и файлами конфигурации вашей игры.

Экспорт Данных

Экспорт вызывается через кнопку Export в верхнем меню приложения. Доступны следующие форматы:

  1. Lua Tables (.lua):

    При использовании плагина автоэкспорта Lua приложение генерирует готовые файлы .lua в виде стандартных ассоциативных массивов (таблиц), возвращаемых через return. Это наиболее производительный способ загрузки данных в Lua-совместимых движках, поскольку файлы компилируются и загружаются нативно, полностью исключая стадию ручного парсинга строк JSON во время выполнения игры.

  2. JSON (.json):

    Экспортирует всю базу данных в один компактный JSON-объект, либо генерирует отдельные JSON-файлы для каждой категории. Идеально подходит для универсального импорта в Unity, Unreal Engine или Godot.

  3. CSV (.csv):

    Экспортирует выбранную категорию в формате плоской таблицы. Удобно для импорта в Google Sheets, Excel или для движков, оптимизированных под табличные структуры.

Импорт Данных

Импорт в DataForge позволяет быстро загружать существующие таблицы баланса или структурированные списки. Процесс импорта полностью автоматизирован: вместо загрузки данных в пустую категорию, редактор **автоматически создает новую категорию** на основе структуры импортируемого файла.

Как устроен процесс импорта:

  • Поддерживаемые форматы: Вы можете импортировать файлы трех типов:
    • JSON (.json) — массивы объектов или ассоциативные словари.
    • CSV (.csv) — плоские таблицы с заголовками.
    • Lua (.lua) — файлы, возвращающие Lua-таблицы (возвращаемое значение парсится через AST-анализатор).
  • Автоматическое создание категории: Имя новой категории и её уникальный ID формируются на основе имени импортируемого файла (например, файл items_db.csv создаст категорию items_db). Если категория с таким именем уже существует в проекте, редактор автоматически добавит числовой суффикс (например, items_db_1).
  • Автогенерация схемы полей (Fields Schema): Вам не требуется настраивать структуру полей заранее. DataForge сканирует свойства импортируемых элементов и автоматически создает подходящие поля, определяя типы данных на лету:
    • Числа распознаются как тип Number.
    • Флаги true/false — как тип Boolean.
    • Массивы — как тип Collection.
    • Остальные значения — как стандартные поля String.
  • Окно настроек импорта (Import Settings): Перед финальной загрузкой открывается модальное окно настроек:
    • Разделитель (для CSV): Возможность указать символ разделения колонок (запятая, точка с запятой и т.д.).
    • Выбор ключевого поля ID: Вы можете указать, какое поле из файла использовать в качестве уникального `id` элемента (например, колонку с именем, артикулом или ключи словаря). Если выбрать вариант none, то ID будут сгенерированы автоматически.
    • Префикс автогенерации ID: Вы можете задать префикс для автогенерируемых ID (по умолчанию используется имя файла с подчеркиванием).

Разработка Плагинов (API)

DataForge поддерживает динамическую загрузку плагинов, написанных на JavaScript. Вы можете расширять функционал редактора, регистрируя новые типы полей, добавляя собственные настройки и взаимодействуя со встроенным Tauri API.

Каждый плагин представляет собой один .js файл, который помещается в локальную папку плагинов приложения. Настройки и метаданные плагина парсятся из JSDoc-комментария в начале файла.

Метаданные плагина

Каждый плагин представляет собой один .js файл. В начале файла должен присутствовать JSDoc-комментарий, содержащий следующие параметры: имя плагина (@name), краткое описание (@description), версию (@version), автора (@author) и перечень регистрируемых типов полей (@fields).

Интерфейс API

При загрузке плагину передаются два глобальных объекта: DataForge (интерфейс API редактора) и React. Доступны следующие методы:

1. Регистрация нового типа поля

DataForge.registerFieldType(pluginId, fieldTypeConfig);

Параметры объекта fieldTypeConfig:

Параметр Тип Описание
id String Уникальный ID типа поля (например, "range_slider").
name String Отображаемое имя типа поля в конструкторе макетов.
icon String Название иконки из библиотеки Lucide (например, "Sliders", "Calendar").
renderConfig Function Компонент React для рендеринга настроек поля в окне редактирования структуры категории. Принимает аргументы { config, onChange }.
renderCell Function Компонент React для рендеринга инпута в форме заполнения элемента. Принимает аргументы { value, onChange, field, rowId, projectSettings }.
renderPreview Function Компонент React для рендеринга предпросмотра значения поля в списках. Принимает аргументы { value, field, projectSettings }.

2. Регистрация настроек плагина

DataForge.registerSetting(pluginId, settingConfig);

Позволяет добавить параметры настройки плагина в глобальное меню настроек приложения. Параметры settingConfig:

Параметр Тип Описание
id String Уникальный ID настройки.
name String Название настройки в интерфейсе.
description String Подсказка или подробное описание настройки.
type String Тип инпута: "string", "boolean", "number", "directory".
default any Значение по умолчанию.

3. Интеграция с ОС через Tauri Bridge

Объект DataForge.Tauri предоставляет методы для безопасной работы с файловой системой пользователя:

  • Tauri.open(options) — вызов диалогового окна выбора файла/директории.
  • Tauri.readTextFile(path) — чтение содержимого текстового файла с диска.
  • Tauri.convertFileSrc(path) — конвертация абсолютного пути к локальному файлу в безопасную ссылку (URL) для отображения в браузере (например, для предпросмотра картинок).
